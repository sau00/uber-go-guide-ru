# Участие в работе

Если вы нашли ошибку или неточность в переводе, откройте issue или пришлите PR.
Изменения содержания самого руководства (а не перевода) лучше сначала
предлагать в [оригинальном репозитории](https://github.com/uber-go/guide).

## Внесение изменений

- `style.md` генерируется из содержимого каталога `src/`.
  Все изменения нужно вносить в файлы в `src/`.
- Для нового раздела создайте файл с коротким именем
  (см. [Имена файлов](#имена-файлов)) и добавьте его в [SUMMARY.md](src/SUMMARY.md).
  В файле должен быть ровно один заголовок первого уровня и любое число подразделов.
- Для примеров кода «плохо/хорошо» используйте таблицы.
- Ссылайтесь на другие разделы по именам их файлов (`[..](foo.md)`).

## Обновление style.md

`style.md` собирается из содержимого `src/` с помощью
[stitchmd](https://github.com/abhinav/stitchmd). Чтобы пересобрать его, выполните:

```bash
make
```

Команда при необходимости установит `stitchmd` и обновит `style.md`.
Закоммитьте результат вместе с изменениями в `src/`.

## Стиль текста

### Переносы строк

Используйте [семантические переносы строк](https://sembr.org/).
Так Markdown-файлы проще ревьюить и редактировать.

### Имена файлов

Имена файлов в src/ примерно следуют схеме:

    {subject}-{desc}.md

где `{subject}` — тема раздела **в единственном числе**
(например, `string`, `struct`, `time`, `var`, `error`),
а `{desc}` — краткое описание из одного-двух слов.
Если названия темы достаточно, `-{desc}` можно опустить.
Имена файлов совпадают с оригиналом, чтобы было проще сверять перевод.

### Примеры кода

Используйте для отступов в примерах кода два пробела:
в примерах, расположенных рядом, место по горизонтали ограничено.

### Примеры «плохо/хорошо»

Создавайте примеры кода, расположенные рядом, по следующему шаблону:

~~~
<table>
<thead><tr><th>Плохо</th><th>Хорошо</th></tr></thead>
<tbody>
<tr><td>

```go
ПЛОХОЙ КОД
```

</td><td>

```go
ХОРОШИЙ КОД
```

</td></tr>
</tbody></table>
~~~

Пустые строки между HTML-тегами и примерами кода обязательны.

Если под примерами нужно добавить подписи или пояснения,
добавьте ещё одну строку таблицы перед строкой `</tbody></table>`.

~~~
<tr>
<td>ОПИСАНИЕ ПЛОХОГО КОДА</td>
<td>ОПИСАНИЕ ХОРОШЕГО КОДА</td>
</tr>
~~~

### Терминология

Чтобы перевод оставался единообразным, придерживайтесь уже принятых терминов:
slice — срез, map — мапа, receiver — получатель, goroutine — горутина,
embedding — встраивание, wrapping — оборачивание, zero value — нулевое значение,
capacity — ёмкость.
